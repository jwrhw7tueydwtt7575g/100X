# TASK: Build Backend IVR State Machine & Audio Engine for WariVerse

## Context & Objective
We are building a zero-cost, Twilio-free In-App IVR System inside WariVerse. Instead of using external paid telephony APIs like Twilio, the frontend app sends DTMF keypresses ('1', '2', '3', '#') and voice audio streams to our FastAPI backend (`wariverse-backend`), which processes IVR menu logic and streams responses back using OpenAI Speech-to-Text (STT) and Text-to-Speech (TTS).

## Architectural Requirements

### 1. Extend FastAPI Backend Router (`app/routers/ivr.py`)
- Create new endpoints:
  - `POST /api/ivr/session/start`: Initializes a new IVR call session with `session_id`, returning initial audio prompt URL/base64 and available DTMF options.
  - `POST /api/ivr/session/dtmf`: Accepts `{ session_id: str, key: str }` to transition state across IVR menus:
    - Main Menu: Language Selection (1: Marathi, 2: Hindi, 3: English)
    - Sub Menu:
      - Option 1: Live Crowd & Queue Status
      - Option 2: Temple Darshan & Token Pass Info
      - Option 3: Nearby Facilities & Seva Offerings
      - Option 4: Emergency SOS & Volunteer Escalation
      - Option 9: Switch to Live Speech Conversation Mode
  - `POST /api/ivr/session/voice`: Accepts recorded speech audio (WAV/AAC/WebM) from the user, uses `VoiceService` with OpenAI Whisper to transcribe, forwards query to `LLMOrchestrator`, and converts LLM response to audio using OpenAI TTS (`tts-1` / `alloy`/`marathi-accent`).

### 2. Implementation & Integration Rules
- Reuse existing services: `LLMOrchestrator`, `VoiceService`, `CrowdService`, and `TempleService`.
- Maintain strict session state using `Session` ORM model with `channel="ivr"`.
- Ensure zero breaking changes to existing REST endpoints (`/api/conversation`, `/api/voice/transcribe`, `/api/voice/speak`).

## Verification & Tests
- Create pytest test suite in `tests/test_ivr.py` validating:
  1. Full DTMF menu flow navigation (Start -> Language Select -> Service Selection -> Dynamic Response).
  2. Voice recording submission and audio response synthesis.
  3. Proper fallback handling for invalid keypresses ("Press 0 to replay menu").
